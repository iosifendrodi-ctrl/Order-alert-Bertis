# Order Alert v1.4 — Close & History

Implemented:
- Clean single close flow in `order.html`.
- Closed orders are read-only in the UI.
- Mandatory `closed_by` field; no default management actor.
- Atomic close transaction.
- Immutable `order_history` snapshot captured at close time.
- Snapshot contains order, lines, alert, verification and close metadata.
- `/history` reads from `order_history`, not the live order rows.
- Closed order details render from the stored snapshot.
- Alert acknowledge/verification/resolve actions are blocked for closed orders.
- Existing v10 shortage logic and configurable thresholds are preserved.
- Existing COSYS integration boundary is preserved.

Lifecycle:
ACTIVE -> RESOLVED -> CLOSED

Acceptance example:
16 ordered / 6 picked / 10 missing = 37.5% picked; with the existing threshold configuration this remains a critical shortage case. After closure, the original values and severity are retained in the snapshot.
